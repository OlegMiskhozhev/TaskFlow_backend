# 🛠️ ПОДГОТОВКА ОКРУЖЕНИЯ

В данном разделе описаны шаги по развертыванию локального окружения разработчика для проекта TaskFlow.

---

### 📦 1. Установка пакетного менеджера

В качестве основного инструмента для управления зависимостями, виртуальными окружениями и запуска скриптов используется менеджер **`uv`**.

#### Инсталляция:
* **macOS / Linux:**
  ```bash
  curl -LsSf https://astral.sh | sh
  ```
* **Windows (PowerShell):**
  ```powershell
  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh | iex"
  ```

*После установки перезапустите терминал и убедитесь в корректности установки командой: `uv --version`.*

---

### 🐳 2. Установка СУБД и контейнеризации Docker

Вся инфраструктура проекта (базы данных PostgreSQL, брокер сообщений Redis, объектное хранилище MinIO) запускается локально в изолированных контейнерах.

Для работы вам потребуется установленный **Docker** и **Docker Compose**. 

* **macOS / Windows / Linux:** Скачайте и установите графическое приложение Docker Desktop в соответствии с [официальной документацией Docker](https://docker.com).

*После установки запустите Docker Desktop и убедитесь в терминале, что утилиты доступны: `docker compose version`.*

---

### 🐍 3. Создание и активация виртуального окружения

Благодаря конфигурации `package = false` в нашем `pyproject.toml`, менеджер `uv` инициализирует проект как чистое веб-приложение, не перегружая систему сборкой пакетов.

Выполните в корневом каталоге проекта для создания локального окружения и установки всех зависимостей:

```bash
# Создание изолированного окружения .venv
uv venv

# Синхронизация и автоматическая установка всех зависимостей (включая dev-группу)
uv sync
```

#### Активация окружения в терминале:
* **macOS / Linux:** `source .venv/bin/activate`
* **Windows (PowerShell):** `.venv\Scripts\Activate.ps1`

> 💡 **Совет для PyCharm / VS Code:** При первой настройке укажите интерпретатором созданную папку `.venv` в корне проекта. IDE автоматически подхватит настройки линтера `ruff` и статического анализатора `mypy`.

---

### 🔑 4. Подготовка переменных окружения

В проекте используется подход **Feature-based конфигурации**. Настройки и секреты каждого микросервиса изолированы и хранятся внутри директорий соответствующих фич.

Для локального запуска вам необходимо создать два файла настроек, скопировав их из шаблонов `.example`:

#### Шаг A. Конфигурация сервиса Задач (Tasks)
```bash
cp tasks/.env.tasks.example tasks/.env.tasks
```
*Откройте `tasks/.env.tasks` и установите актуальные локальные значения (пароли к БД, секретные ключи, доступы к SMTP и OAuth2).*

#### Шаг Б. Конфигурация сервиса Потоков (Flow)
```bash
cp flow/.env.flow.example flow/.env.flow
```
*Откройте `flow/.env.flow` и настройте доступы к базе данных `flow_db` и ключи шифрования.*

> ⚠️ **ВАЖНО:** Файлы `.env.tasks` и `.env.flow` содержат конфиденциальные данные и защищены правилами `.gitignore`. **Категорически запрещено** отправлять их в удаленный репозиторий. Разработчик обязан самостоятельно следить за тем, чтобы пароли к СУБД в обоих файлах совпадали для корректного монтирования Docker Volumes.
