# 🚀 ЗАПУСК ПРОЕКТА

Перед запуском проекта убедитесь, что ваша машина полностью настроена в соответствии с разделом [ПОДГОТОВКА ОКРУЖЕНИЯ](environment.md).

Все команды выполняются из **корневого каталога** репозитория с помощью утилиты `make`.

---

### 🛠️ 1. Локальный запуск для разработки (Бэк на ПК + Инфраструктура в Docker)

Этот режим используется для повседневной разработки. Инфраструктура работает в фоне, а бэкенд запускается на вашем компьютере с поддержкой автоперезагрузки кода (Hot Reload).

1. **Запустите компоненты инфраструктуры** (PostgreSQL, Redis, MinIO, Celery):
   ```bash
   make up-infra
   ```
2. **Накатите миграции** баз данных (выполняется один раз при первом старте или изменениях в моделях):
   ```bash
   make migrate-tasks
   make migrate-flow
   ```
3. **Запустите бэкенд-сервисы** (каждый сервис запускается в отдельной вкладке терминала):
   ```bash
   # Запуск сервиса Проектов (будет доступен на http://localhost:8000)
   make run-tasks

   # Запуск сервиса Flow (будет доступен на http://localhost:8001)
   make run-flow
   ```

*Посмотреть состояние и логи фоновой инфраструктуры можно командой: `make logs-infra`.*
*Остановить инфраструктуру: `make down-infra`.*

---

### 🐳 2. Полный запуск пула сервисов (Всё внутри Docker)

Этот режим используется для проверки полной сборки проекта перед деплоем на сервер или стейджинг. Всё общение между сервисами скрыто внутри докер-сетей, а единственной точкой входа наружу становится шлюз Nginx.

1. **Запустите весь стек сервисов в фоне**:
   ```bash
   make run-full
   ```
2. **При необходимости загрузите тестовые данные** в базу данных:
   ```bash
   docker exec -it tasks_backend python3 test_data/load_test_data.py
   ```

#### Доступные адреса (через API Gateway):
* `http://localhost/api/tasks` — раздел проектов и задач (tasks)
* `http://localhost/api/tasks/redoc` — документация API задач
* `http://localhost/api/flow` — раздел свободных заметок (flow)
* `http://localhost/api/flow/redoc` — документация API потоков
* `http://localhost:9001` — веб-админка хранилища MinIO

*Смотреть логи всего стека: `make logs-full`.*
*Остановить весь стек: `make down-full`.*
